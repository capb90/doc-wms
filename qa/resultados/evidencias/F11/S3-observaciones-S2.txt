## 4. Comprobante de pago de 6 MB por API (POST billing/payments/vouchers, multipart)
seis-mb.pdf (6291471 bytes) → "description":"Adjunte el comprobante del pago." HTTP 400 
cinco3-mb.pdf (5542895 bytes) → "description":"Adjunte el comprobante del pago." HTTP 400 
comprobante-qa.pdf (72306 bytes) → HTTP 200 
Conclusión 4 → DEFECTO TRIVIAL (DEF-F11-015): el criterio 3 de CHG-29 pide «El comprobante no puede superar 5 MB.» para un archivo de 6 MB. La pantalla lo cumple (valida antes de enviar, S2), pero el API responde «Adjunte el comprobante del pago.» a todo archivo mayor que el límite de la petición (~5,3 MB): el límite descarta el archivo antes de la validación de tamaño.

## 5. Título «Recurso duplicado.» en los 409 de negocio → SIN FICHA (observación)
El API pone Title = «Recurso duplicado.» a toda ConflictException (GlobalExceptionHandler.cs:59), también a los conflictos de estado (p. ej. R-EXP: «No se puede cerrar el pesaje de salida: la orden 2026OC00010 aún no está cargada…»). La interfaz no usa ese título: el aviso global titula «Conflicto» (api-error.ts, summaryForStatus) y los componentes ponen el suyo; en báscula, el repesaje de QAM101 sin guía muestra «Error al registrar peso — No se puede cerrar el pesaje de salida: la orden 2026OC00003 es de importación y no tiene guía de salida vigente…». Solo lo ve quien consume el API; la descripción es correcta. Recomendación: título genérico «Conflicto con el estado actual.» o por tipo.
