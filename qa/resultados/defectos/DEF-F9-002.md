# DEF-F9-002 — Vigilancia y Bodega se cruzan: Vigilancia entra a las páginas y al API de Bodega, y Bodega registra ingresos y salidas de Vigilancia

| Módulo | Seguridad / Vigilancia / Bodega |
| Casos | F9-MEN-004, F9-PAG-004, F9-API-019 |
| Riesgo del plan | R-ADM-09 |
| Rol / usuario | vigilancia, bodega |
| Ambiente y commits | Local · FE `1501cd6` · BE `191d4b1` |
| Estado | Verificado |

## Pasos para reproducir
1. Con `vigilancia`: abrir por URL `/warehouse`, `/warehouse/inventory`, `/warehouse/receptions`, `/warehouse/loading-orders`.
2. Con el token de `vigilancia`: `POST warehouse/receptions/without-weighbridge`, `warehouse/forklift-uses/start`, `warehouse/loading-orders/{id}/execute`, `GET warehouse/inventory/deposits`.
3. Con el token de `bodega`: `POST entry-logs`, `POST entry-logs/{id}/departure`.

## Resultado esperado
Decisión del usuario (2-oct-2026): Vigilancia solo ve y usa Vigilancia. Bodega tampoco opera la portería. 403 / access-denied en ambos sentidos.

## Resultado obtenido
1. Las 4 páginas de Bodega cargan para `vigilancia` (el menú no las muestra). 2. Las 44 operaciones con `WarehouseAccess` pasan la autorización **para los dos roles**: las de Bodega (recepciones, recepción directa, montacargas, cargue, inventario, ubicaciones, novedades) para Receiving, y las de portería de `EntryLogController` (crear ingreso, salida, autorizaciones de salida, manifiestos) para Warehouse.

## Impacto
Separación de funciones rota: un vigilante puede recibir mercancía, ejecutar cargues o ajustar ubicaciones; un bodeguero puede registrar ingresos y salidas de camiones.

## Pista técnica
`WmsAuthentication.cs:78-79`: `WarehouseAccess` = Admin, Warehouse, **Receiving**; `EntryLogController.cs:19` usa `WarehouseAccess`. Crear una política `ReceivingAccess` (Admin, Receiving) para la portería y quitar Receiving de `WarehouseAccess`; en el front, `requiredRoles` de `pages/warehouse/**` sin Receiving.
