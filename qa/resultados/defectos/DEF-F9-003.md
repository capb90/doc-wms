# DEF-F9-003 — El API guarda como autor el usuario que envía el cliente (autorizó la salida, autorizó la recepción, completó el cargue) y la firma del cargue es opcional

| Campo | Valor |
|---|---|
| Severidad | MAJOR |
| Módulo | Seguridad / Auditoría operativa |
| Casos | F9-API-020 |
| Riesgo del plan | R-BOD-08 |
| Rol / usuario | vigilancia, bodega |
| Ambiente y commits | Local · FE `1501cd6` · BE `191d4b1` |
| Estado | Verificado |

## Pasos para reproducir
1. `vigilancia` registra la salida de QAF901 con `departureAuthorizedById` = ID de `facturacion`.
2. `bodega` hace una recepción sin báscula (2026INSP00008) con `authorizedByUserId` = ID de `capb90`.
3. Revisar `entry_logs.departure_authorized_by_id` y `inventory_movements.authorized_by`.

## Resultado esperado
El autor es siempre el usuario del token; el cliente no puede elegirlo. La firma del conductor es obligatoria también en el API (como en la pantalla).

## Resultado obtenido
La salida queda autorizada por **facturacion** (la registró vigilancia) y el movimiento de inventario por **capb90** (lo hizo bodega). `ExecuteLoadingOrderCommandHandler.cs:47` toma `CompletedBy` del cuerpo; el validador de la firma solo limita el tamaño (`ExecuteLoadingOrderCommandValidator.cs:39-40`).

## Impacto
Se puede atribuir una operación a otra persona; la auditoría operativa (quién autorizó una salida o una recepción) no es confiable.

## Pista técnica
Tomar el usuario de `ICurrentUserService` en los handlers y eliminar `DepartureAuthorizedById`, `AuthorizedByUserId` y `CompletedBy` de los requests; regla `NotEmpty` para `SignatureDriver`.
