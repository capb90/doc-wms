# DEF-F3-004 — Descartar una operación no libera el camión y permite cobrar el servicio descartado

| Campo | Valor |
|---|---|
| Severidad | CRITICAL |
| Módulo | Báscula |
| Casos | F3-REC-006, F3-REC-007, F3-REC-008 |
| Riesgo del plan | R-BAS-02 |
| Rol / usuario | bascula |
| Ambiente y commits | Local · FE `a5289ce` · BE `191d4b1` |
| Estado | Verificado |

## Pasos para reproducir
1. Registrar un ingreso (QAC402, QA-CP-0402) y no cobrar.
2. Recuperar operaciones → Descartar → confirmar («Operación descartada»).
3. Mirar la cola; intentar registrar otra vez el camión; intentar cobrar el servicio que la cola sigue mostrando.

## Resultado esperado
El camión vuelve a «Sin iniciar» y se puede registrar de nuevo; el servicio descartado no se puede cobrar.

## Resultado obtenido
Depósito 2026BA00003 anulado (correcto), pero el camión sigue **«Por cobrar» (PendingPayment)** con el `serviceRecordId` descartado; registrar de nuevo → 409 «El entry log ya tiene un servicio asignado.»; `POST storage/process-payment` sobre el servicio descartado → **200**, crea ciclo `23ece56f…` y factura.

## Impacto
Camión bloqueado en la cola y cobro de un servicio inexistente (dinero sin operación).

## Pista técnica
`DiscardIncompleteOperationHandler` no borra el enlace `ServiceRecordEntryLog`; la cola y el cobro no filtran servicios `Discarded`.
