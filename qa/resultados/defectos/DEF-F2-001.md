# DEF-F2-001 — La búsqueda de placa por coincidencia parcial registra el ingreso al vehículo equivocado

| Campo | Valor |
|---|---|
| Severidad | CRITICAL |
| Módulo | Vigilancia |
| Casos | F2-ING-007, F2-ING-010, F2-HIS-003 |
| Riesgo del plan | R-VIG-01 |
| Rol / usuario | vigilancia |
| Ambiente y commits | Local · FE `a5289ce` · BE `191d4b1` |
| Estado | Verificado |

## Pasos para reproducir
1. Con `QAA102` existente y sin ingreso abierto, en Vigilancia → Ingreso escribir `AA102` + Enter.
2. Elegir motivo «Otro» → Registrar ingreso.
3. Con `QAB201` (ingreso abierto) existente, escribir `QAB20` + Enter.
4. Historial → filtrar por placa `QAB20`.

## Resultado esperado
1–2: «No existe, se creará al registrar» y un ingreso para el vehículo `AA102` (o rechazo por formato). 3: igual, es otra placa. 4: todos los ingresos cuyas placas contienen `QAB20`.

## Resultado obtenido
1–2: la pantalla dice «Vehículo encontrado.», el aviso dice «Ingreso registrado Placa AA102», pero el ingreso queda a nombre de **`QAA102`** (comprobado en `entry-logs?hasDeparture=false` y en Salida).
3: «Vehículo encontrado.» + «Esta placa ya tiene un ingreso abierto desde …» → no deja registrar `QAB20`. Igual con `AB`.
4: solo aparece `QAB201`; faltan QAB202–QAB205.

## Impacto
Un error de digitación en portería asigna el camión a otro vehículo sin advertencia: trazabilidad, báscula, depósito y facturación quedan sobre el vehículo equivocado. También impide registrar placas que son prefijo de otras.

## Pista técnica
El ingreso y el historial resuelven la placa con `GET /vehicles?licensePlate=…&pageSize=1`, que hace `ILIKE %x%` (`GetAllVehiclesHandler.cs:18`) y toma el primero (también inactivos). Debería usarse una búsqueda exacta (p. ej. `weighbridge/vehicles/by-plate/{plate}`, que normaliza y es exacta).
