# DEF-F9-006 — Un cuerpo JSON mal formado devuelve 500 con el texto interno de la excepción

| Campo | Valor |
|---|---|
| Severidad | MINOR |
| Módulo | API / Errores |
| Casos | F9-API-* (sondeo) |
| Riesgo del plan | R-ADM-06 |
| Rol / usuario | todos |
| Ambiente y commits | Local · FE `1501cd6` · BE `191d4b1` |
| Estado | Verificado |

## Pasos para reproducir
`POST product` (o cualquier escritura con cuerpo) con `Content-Type: application/json` y el cuerpo `{"__qa":` (JSON incompleto).

## Resultado esperado
400 «El cuerpo de la solicitud no es válido».

## Resultado obtenido
500 «Error del servidor» con `description` «[ArgumentNullException] Value cannot be null. (Parameter 'request')». En el sondeo, Admin recibió 139 respuestas 500 de este tipo. Es la misma causa que DEF-F4-002 (el request llega null al handler).

## Impacto
Errores internos expuestos y códigos engañosos (la falla es del cliente).

## Pista técnica
Validar `request == null` en el pipeline (comportamiento de MediatR o filtro) y devolver 400; no exponer el tipo de excepción en `description`.
