# DEF-F6-001 — La tarifa de almacenamiento se toma de otra modalidad: el convenio IMP cobra EXP e INSP y la tarifa base EXP cobra INSP

| Campo | Valor |
|---|---|
| Severidad | CRITICAL |
| Módulo | Facturación |
| Casos | F6-TAR-004, F6-TAR-007, F6-INV-011, F6-ACC-005 |
| Riesgo del plan | R-FAC-15 |
| Rol / usuario | facturacion |
| Ambiente y commits | Local · FE `41c19cd` · BE `191d4b1` |
| Estado | Verificado |

## Pasos para reproducir
1. QA Cliente Uno tiene ALMACENAMIENTO `PERCENTAGE_OF_VALUE` solo para IMP001 (0,255 %, mínimo 184.000).
2. Confirmar 2026EXP00001/00002 (EXP, COP 50M y 3M) y 2026INSP00001 (INSP, COP 5M).
3. QA Cliente Mora (sin convenio) confirma 2026INSP00002; la tarifa base tiene `FIXED` 150.000 solo para EXP001.

## Resultado esperado
EXP: tarifa base EXP 150.000 + IVA = 178.500. INSP: sin regla → mínimo INSP ($0) con advertencia.

## Resultado obtenido
EXP00001, EXP00002 e INSP00001: «Almacenamiento (mínimo aplicado)» 184.000 con fuente «Acuerdo (nivel 1)». INSP00002 (Mora): 150.000 + IVA = 178.500 con la tarifa EXP. Solo INSP00003 (sin valor de mercancía) dio $0.

## Impacto
Cobros errados en toda factura de una modalidad distinta a la de la regla (aquí +5.500 por EXP, +184.000 y +178.500 por INSP).

## Pista técnica
`BillingResolver` (escalera de especificidad): el peldaño con modalidad no filtra por la modalidad del depósito, en convenio y en tarifa base.
