# DEF-F1-001 — Productos: `GET`, `POST` y `PATCH product` responden 500 (NullReferenceException)

| Módulo | Administración |

| Riesgo del plan | nuevo |
| Rol / usuario | capb90 (Admin) |
| Ambiente y commits | Local · FE `a5289ce` · BE `191d4b1` |
| Estado | Verificado |

## Pasos para reproducir
1. Administración → Productos → Crear: nombre «QA Cebolla», unidad Bulto, embalaje QA-CAJA → «Crear Producto».
2. Abrir el detalle de cualquier producto (también los sembrados, p. ej. «Granos») en `/admin/products/{id}`.
3. Por API: `GET /product/{id}`, `PATCH /product/{id}` con cualquier cambio.

## Resultado esperado
El alta, la edición y el detalle responden 2xx con el producto.

## Resultado obtenido
- Alta: aviso «Error 500 [NullReferenceException] Object reference not set to an instance of an object.», pero el producto **queda guardado** (aparece en el listado). Si el operario reintenta, recibe 409 por nombre duplicado.
- Detalle: «No se pudo cargar la información del producto» para todos los productos (sembrados y nuevos). La página de edición depende del mismo `GET`.
- `PATCH /product/{id}` (editar, desactivar): 500, pero el cambio **se guarda**.
- `GET /product?all=true` (listado, lo que usa báscula) funciona.

## Impacto
Administración no puede ver ni editar productos desde la UI; el operario ve errores en operaciones que sí se aplicaron (riesgo de duplicados y de datos cambiados sin saberlo).

## Pista técnica
`Wms.Application/Products/Commands/CreateProduct/CreateProductHandler.cs`: tras `SaveChangesAsync` llama a `mapper.Map(product)` sin cargar navegaciones (p. ej. la unidad de medida). Probablemente el mismo `ProductMapper.Map` falla en `GET/PATCH` por id.
