## Precondiciones y datos
Cualquier usuario con permiso de alta de terceros (Admin o Comercio Exterior). Rol de negocio CUSTOMER por su Id.

## Pasos para reproducir
1. `POST /api/v1/stakeholder` con un cuerpo JSON válido cuyo `idType` es `"NIT"` (en mayúsculas; la pantalla envía `"Nit"`), por ejemplo nombre «QA F11 Tipo Invalido», `idNumber` 900199902 y `businessRoles` con el Id de CUSTOMER.
2. Observar la respuesta.

## Resultado esperado
400 de validación con el campo (`IdType`) y un mensaje de negocio en español, como pide CHG-48 («un cuerpo inválido responde 400 con el campo») y como ya responde el mismo endpoint cuando un rol no es un Guid («El ID de un rol no tiene un formato de Guid válido.»).

## Resultado obtenido
`500 Error del servidor` con `description: "[ArgumentException] Requested value 'NIT' was not found."` (texto interno de .NET en inglés). No se crea el tercero.

## Evidencia
- Petición: `POST /api/v1/stakeholder` → 500 (respuesta en `docs/qa/resultados/evidencias/F11/S1-hallazgo-idtype-500.txt`).
- Log del API: `System.ArgumentException: Requested value 'NIT' was not found.` en `CreateStakeholderHandler.Handle` (`Enum.Parse<IdentificationType>(request.IdType)`), después del `ValidationBehavior`.
- Con `idType: "Nit"` la misma petición responde 201 (`S1-DEF-F9-001-matriz.txt`).

## Impacto
Solo por API: la pantalla envía valores válidos. Un integrador o un cliente del API recibe un 500 con texto técnico en lugar de un 400 que indique el campo. Sin efecto en datos.

## Pista técnica (opcional)
`Wms.Application/Stakeholders/Commands/CreateStakeholder/CreateStakeholderHandler.cs:17` usa `Enum.Parse` sin validar; el validador del comando no comprueba `IdType` contra `IdentificationType`. Revisar también `UpdateStakeholder` si comparte el patrón.
