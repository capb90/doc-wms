# DEF-F2-003 — El API acepta fecha de ingreso futura y salida anterior al ingreso

## Pasos para reproducir
1. `POST /entry-logs` con `dateTimeEntry` = hoy + 3 días.
2. Registrar la salida de ese ingreso (hoy).

## Resultado esperado
1: 400 «La fecha de ingreso no puede ser futura» (como en la corrección). 2: la salida no puede ser anterior al ingreso.

## Resultado obtenido
1: 201 con `dateTimeEntry` 2026-10-05. 2: salida 2026-10-02 aceptada; la tarjeta mostraba «0m» en planta. `departureAuthorizedById` y `dateTimeDeparture` los envía el cliente sin validar.

## Impacto
Fechas imposibles en portería, que alimentan la fecha de ingreso del depósito, el abandono y la trazabilidad. Hoy solo por API (la UI no envía fechas).
