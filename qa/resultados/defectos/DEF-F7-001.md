# DEF-F7-001 — La auditoría guarda el PasswordHash y el SecurityStamp de los usuarios

| Campo | Valor |
|---|---|
| Severidad | CRITICAL |
| Módulo | Seguridad / Admin |
| Casos | F7-AUD-006 |
| Riesgo del plan | R-ADM-12 ★ |
| Rol / usuario | capb90 |
| Ambiente y commits | Local · FE `1501cd6` · BE `191d4b1` |
| Estado | Verificado |

## Pasos para reproducir
1. Admin reinicia la contraseña de un usuario de prueba (`POST user/{id}/reset-password`, usuario `qa_cambio`).
2. `GET administration/audit-logs` (o `/admin/audit`), tabla ApplicationUser.

## Resultado esperado
Los campos sensibles (PasswordHash, SecurityStamp, ConcurrencyStamp) se excluyen o enmascaran en `previousValue`/`newValue`.

## Resultado obtenido
Los dos registros Update de ApplicationUser contienen `PasswordHash` (hash completo) y `SecurityStamp` antes y después. Los valores no se copian en este informe.

## Impacto
Exposición de hashes de contraseña y sellos de seguridad a cualquier usuario con acceso a la auditoría; permite ataques de fuerza bruta fuera de línea e invalida el propósito del SecurityStamp.

## Pista técnica
Interceptor de auditoría: lista de exclusión de propiedades sensibles para `ApplicationUser` (y revisar registros ya guardados).
